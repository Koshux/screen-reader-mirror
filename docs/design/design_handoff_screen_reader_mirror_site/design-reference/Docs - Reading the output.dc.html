Docs · Reading the output

Four views, one list

Every surface shows the same reading order four ways. Only the first is speech; the others exist to help you find the element and fix it. This page explains a row, the flags, the notes, and every empty, loading and error state you can meet.

Views

Spoken, Preview, Nodes, JSON

ViewWhat it is for SpokenWhat a screen reader says, in order, in the chosen profile's words, and nothing else. Notes in the dashed yellow box come from the mirror, not the screen reader, and say why a row is flagged. PreviewThe same HTML with its CSS removed, browser defaults only. Structure that survives without styling is structure a screen reader can use. A heading that turns into plain text here will be plain text to NVDA. NodesPosition, role, name, level and flag per item, as a table. Hover a row and the element lights up on the page; hover the page and the row lights up. JSONThe list as data, for an issue, a snapshot or a script. Exactly what linearize() returns.

Anatomy

Reading one row

5button (no name)unnamed
Note · An interactive element with no accessible name. A screen reader says only "button". Give it text, an aria-label, or an aria-labelledby.
  • Position: where it falls in reading order. Matches the number in Nodes and the index in JSON.
  • Role, muted: the computed WAI-ARIA role. An explicit role wins; otherwise the conditional implicit one (<a> is a link only with href). Bare text runs are text.
  • Name: the accessible name per AccName 1.2. Elements named from their content are not read twice.
  • Flag: worth checking. Not a score, not a verdict.
  • Note: from the mirror. Never part of the speech.

Things that are not flags but are shown: a styled span that looks like a heading appears as text and is marked "not in H" in Headings mode; a clickable div is "not focusable" in Tab order; a hint beside a field that is not linked is "hint not linked" in Forms mode.
