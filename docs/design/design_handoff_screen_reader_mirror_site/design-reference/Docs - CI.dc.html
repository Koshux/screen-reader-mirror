Docs · Continuous integration

The same engine, with nobody at the keyboard

Manual testing compares the mirror with a screen reader. CI has no screen reader and no person, so it checks the engine's output against two things that need neither: rules and a snapshot.

What CI checks

Two gates

  • Flags: fail when any node carries unnamed or missingAlt, or when heading levels skip. No setup; catches the common mistakes on every build.
  • Snapshot: commit the reading order like a test snapshot. Fail when it changes. Catches the quiet regressions: a heading that became a styled span, a button that lost its label, a landmark that vanished.

Three places to run them: a unit test, the CLI in a workflow, or inside an existing Playwright suite.

1 · Unit test

In jsdom, next to your component tests

import { linearize } from "screen-reader-mirror";

test("orders page reads in order", () => {
  render(<Orders />);
  const nodes = linearize(screen.getByRole("main"));
  expect(nodes.map(n => [n.role, n.name, n.level])).toMatchSnapshot();
  expect(nodes.filter(n => n.flags?.unnamed)).toEqual([]);
});

The result is plain data, so toMatchSnapshot works unchanged. Styles do not load in jsdom, so display:none set by a stylesheet is not seen; keep visibility checks for the browser run or pass options.getComputedStyle.

2 · CLI in a workflow

After the preview deploys

  1. 1

    First run writes the snapshot

    npx screen-reader-mirror https://preview.example.com/orders \
  --source ax --fail-on unnamed,missingAlt,heading-skip \
  --snapshot a11y/orders.json

    You should see "no snapshot, wrote a11y/orders.json" and exit 0. Commit the file. From now on it is the known-good order.

  2. 2

    A pull request that changes the order fails

    ✗ snapshot a11y/orders.json: 1 removed, 1 added
  - 3  heading "Recent" level 2        main > h2
  + 3  text    "Recent"
✗ flags: 1 unnamed
  5  button ""                          main > div.toolbar > button:nth-child(1)
exit 1

    The check on the PR goes red. The diff is the review: an h2 became a div, and a button lost its label.

  3. 3

    Fix it, or update on purpose

    Fix the markup and push; the check goes green. If the change was intended, run with --update, commit the new snapshot, and the PR shows before and after. Never fix and update in the same commit; one or the other, so the history says which it was.

Names that change every build

Dates, counts, user names. Mask them so the row still counts without its text: --mask ".order-date, [data-live]". Masked names appear as • in the snapshot.

Pages that need more

  • Behind login: --storage-state auth.json from a Playwright setup step, or --cookie name=value. Neither is written to the report.
  • Loads late: the walk runs at network idle by default. --wait-for "main" waits for an element; --wait 2000 adds a pause. Unloaded frames read as empty documents.
  • Many pages: --pages a11y/pages.txt, one URL per line. One snapshot and one report per page, one exit code for the run.
  • Source: --source ax is the recommended default on Chromium runners; --source dom matches the bookmarklet.

A complete workflow

GitHub Actions

# .github/workflows/a11y.yml
name: Reading order
on: [pull_request]
jobs:
  mirror:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npx playwright install chromium
      - run: npx screen-reader-mirror --pages a11y/pages.txt \
            --source ax --wait-for "main" \
            --fail-on unnamed,missingAlt,heading-skip \
            --snapshot a11y/snapshots/ --report a11y/report/
      - if: failure()
        uses: actions/upload-artifact@v4
        with: { name: mirror-report, path: a11y/report/ }

Any CI works the same way: Node, a Chromium, one command, exit code.

Reading a failure

The report, and opening it in a surface

{
  "page": "https://preview.example.com/orders",
  "engine": "screen-reader-mirror 0.4.1", "browser": "chromium 131", "source": "ax",
  "nodes": [ { "role": "main", "name": "" }, { "role": "heading", "name": "Orders", "level": 1 }, … ],
  "diff": {
    "removed": [ { "at": 3, "role": "heading", "name": "Recent", "level": 2, "selector": "main > h2" } ],
    "added":   [ { "at": 3, "role": "text",    "name": "Recent" } ],
    "changed": []
  },
  "flags": [ { "at": 5, "role": "button", "flag": "unnamed", "selector": "main > div.toolbar > button:nth-child(1)" } ],
  "verdict": "fail", "reasons": ["snapshot: 1 removed, 1 added", "flags: 1 unnamed"]
}
  1. 1

    Download the artifact

    On the failed run, Artifacts › mirror-report. Unzip.

  2. 2

    Open it in the demo

    On the demo, drop orders.json on the paste box. The Nodes view shows the list with removed rows struck through and added rows marked; the Preview is empty because a report has no HTML.

  3. 3

    Or open it in the extension

    On the preview page itself, side panel › Capture › Imported log, drop the report. Rows line up against the live page so you can click a removed row and see where it was.

Exit codes

What the number means

CodeMeans0Every gate passed, or none were asked for.1A gate failed: a flag in --fail-on, a snapshot diff, or a divergence with --capture.2The page could not be read: navigation failed, timed out, or the browser is missing. Not an accessibility result.

Limits

What CI cannot do

Capture needs a screen reader, and a screen reader needs a desktop session with a person at it. --capture is for a tester's machine (Testing with NVDA). CI tells you the structure changed or a rule fired; it cannot tell you what NVDA said. Keep the two apart and the results stay honest.
