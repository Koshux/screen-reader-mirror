linearize, and what it returns

One function, one type. Everything a surface shows is derived from this. Items marked Proposed are designed but not yet in a release.

Function 0.x

linearize(root, options?)

import { linearize } from "screen-reader-mirror";
function linearize(root: Element, options?: LinearizeOptions): InterpretationNode[];

Walks the composed tree under root in DOM order and returns one entry per thing a screen reader would land on. Pure: no network, no side effects, no live node references in the result. CSS reordering (order, positioning) is intentionally not reflected.

Options

OptionUse getComputedStyle(el)Override the style source for jsdom, happy-dom or non-browser hosts. Decides display:none and visibility:hidden. getShadowRoot(host)Supply a closed shadow root the DOM hides. Defaults to el.shadowRoot, so closed roots read as their light children.

Type 0.x

InterpretationNode

interface InterpretationNode {
  role: string;                 // computed ARIA role, or "text"
  name: string;                 // accessible name, may be ""
  level?: number;               // headings only
  flags?: { unnamed?: boolean; missingAlt?: boolean; unreachable?: boolean };
  live?: {                      // live regions only
    politeness: "polite" | "assertive";
    atomic: boolean;
    relevant: Array<"additions" | "removals" | "text">;
    busy?: true;
  };
  ref?: { tag: string; shadow?: true; frame?: number };
}

Capture Proposed

capture.connect, compare

import { capture, compare } from "screen-reader-mirror/capture";

const bridge = await capture.connect({ port?: 7331, pair: "4821" });
bridge.on("utterance", (u: Utterance) => { … });
bridge.on("status", (s: "connected" | "no-speech" | "lost") => { … });
bridge.close();

interface Utterance { text: string; at: number; reader: "nvda" | "jaws" | "voiceover" | "unknown"; }

function compare(nodes: InterpretationNode[], u: Utterance, profile?: Profile):
  { row?: InterpretationNode; at?: number; verdict: "match" | "differs" | "extra" };

compare aligns by order first, then by text, and remembers the last matched position between calls so a sequence of utterances walks the list. "extra" is an utterance with no row (such as "clickable"); it is attached to the nearest row, never counted as a divergence.

Profiles Proposed

speak(nodes, profile)

import { speak } from "screen-reader-mirror/profiles";
type Profile = "generic" | "nvda" | "jaws" | "voiceover";
function speak(nodes: InterpretationNode[], profile: Profile, opts?: SpeakOptions): string[];

One string per node in that screen reader's default phrasing. SpeakOptions mirror the Speech settings: landmarks, heading levels, table dimensions, punctuation. Profiles are tracked on the roadmap; until they land, every surface uses Generic.

Versioning

What counts as breaking

  • Any change to the shape of InterpretationNode, even in 0.x, is a minor bump and marked breaking in the changelog.
  • A change in computed output for the same HTML (a new role rule, a fixed name) is a patch, listed under "Output changes" with the fixture that covers it. Snapshots will show it.
  • Node 20+, evergreen browsers. ESM only.
