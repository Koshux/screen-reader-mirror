Docs · Testing with NVDA

The mirror beside a real screen reader

The mirror predicts what a screen reader will say. NVDA is the screen reader most testers run. Put the two side by side and every difference becomes a row you can point at. This page gets you there from a blank Windows machine, then explains the four controls above every list.

Set up

Five steps, fifteen minutes the first time

You need three things on one Windows computer: NVDA, Node, and the mirror in any form. Each step says what to type, what you should see, and what to do if you do not.

  1. 1

    Install NVDA

    NVDA is a free screen reader. Download it from nvaccess.org/download, run the installer, keep the defaults, let it start. It begins talking.

    Open its Speech Viewer: press Insert + N for the NVDA menu, then Tools › Speech Viewer. A small window shows every word NVDA says, as text.

    You should see the Speech Viewer fill with text as you move around. Leave it open; the bridge reads from it. If NVDA is silent: Insert + S cycles speech mode; choose "talk".

  2. 2

    Install Node

    Node runs the bridge. Download the LTS from nodejs.org, run the installer, keep the defaults. Open a terminal: press the Windows key, type terminal, Enter.

    > node --version
v22.11.0

    You should see v20 or higher. If not: close the terminal and open a new one; the installer only reaches new windows.

  3. 3

    Start the bridge

    In that terminal, one line. The first run downloads the tool. Leave this window open while you test.

    > npx screen-reader-mirror listen

● NVDA 2025.1 detected
  Bridge on  ws://localhost:7331
  Pair code  4 8 2 1

    You should see the dot, NVDA's version and a four-digit code. If it says "no screen reader found": NVDA is not running or Speech Viewer is closed; fix that and the line updates by itself. "EADDRINUSE": the port is taken; add --port 7332.

  4. 4

    Open the mirror and pair

    Any install works; they all ask for the same code once.

    • Bookmarklet: open the page you want to test, click the Mirror this page bookmark.
    • Extension: click the sr icon, Open side panel.
    • CLI: a second terminal, npx screen-reader-mirror <url> --capture bridge --headed.

    You should see "Bridge found on this machine" and four boxes for the code. Type it. The Capture pill turns green: NVDA · live. If there is no "Bridge found": the step 3 window closed, or the port changed; the panel has a field for the port. Three wrong codes and the terminal prints a new one.

  5. 5

    Press keys, read both columns

    Click once inside the web page so NVDA is reading it. Press ↓ to move one item at a time. The left column is what the mirror expected; the right fills with what NVDA said.

The four controls

Source, Profile, Mode, Capture

Every Spoken list has the same strip above it. Left to right: where the tree came from, how it is phrased, how you are moving, and what a real screen reader said.

Switching source re-reads the page. Rows that changed keep both readings, so DOM-walk and AX-tree disagreements become a list.

Profile

Generic, NVDA, JAWS, VoiceOver. Same nodes, different words: "heading level 1, Orders" against "Orders heading level 1". Switching never re-reads the page. When NVDA is paired, Profile sets itself to NVDA.

With Capture on, the panel follows the real keys: press H in NVDA and the right column fills with what it said at each heading.

Capture

Off, bridge, or imported log. Rows align by order, then by text. A row that differs carries both strings. A row only one side has is left empty on the other. Nothing is ever hidden to make the columns tidy.

Per install

Where the two columns appear

  • Bookmarklet: the panel over the page widens into two columns. It connects to the bridge from the page; localhost counts as a secure origin, so https pages are allowed to.
  • Extension: the side panel splits. Settings has a Capture section: auto-connect, pairing, follow NVDA's keys, show extra utterances. See Settings.
  • CLI: --capture bridge --headed opens the page in a visible browser and prints rows with timestamps as NVDA speaks. Ctrl+C writes mirror-session-<date>.json.
  • Package: capture.connect() subscribes to the bridge; compare(nodes, utterance) returns the matched row and a verdict. Build your own view. See API.

Without a bridge

Import a log

  1. 1

    Get the text

    NVDA: Speech Viewer, select all, copy. JAWS: the speech history window. VoiceOver: the captions panel, or a session report from someone else's bridge.

  2. 2

    Drop or paste it

    Capture › Imported log. Drop the file or paste into the box.

    You should see "Recognised: NVDA Speech Viewer · 6 utterances" (or JAWS, VoiceOver, session report). If it says "Plain text · 14 lines": the shape was not recognised; each line is treated as one utterance. Pick the screen reader by hand so the right profile is used.

  3. 3

    Compare

    Same two columns as live, without the clock. Timestamps, if the log has them, turn on the live-region timeline.

The log stays in the tab. It is not stored and not sent.

When the mirror is wrong

Report a divergence

  1. 1

    Click "Report divergence" on the row

    Appears under any row marked differs.

  2. 2

    Review what will be sent

    A sheet lists exactly what goes in the issue: the mirror's row, the screen reader's row, profile, source, versions of the engine, browser and screen reader, the element's selector, and the smallest HTML around it (about 20 lines). Page URL and anything else are left out unless you add them. Edit any line.

  3. 3

    Send

    Opens a pre-filled GitHub issue in a new tab. Nothing leaves the machine until you press Submit there. Known divergences are listed on Divergences; the sheet tells you if yours is already there.
