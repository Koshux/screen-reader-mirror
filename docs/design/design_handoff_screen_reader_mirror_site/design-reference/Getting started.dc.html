Getting started

Run the mirror on your own pages

Four ways in. The bookmarklet needs nothing installed, the package goes in your build and tests, the extension comes from a store, or as a signed download you install yourself, for pages behind a sign-in. All three run the same engine and show the same four views as the demo. Nothing leaves your browser.

Bookmarklet

Nothing to install

One drag, then one click on any page you can open. It loads the engine from the CDN into the tab and draws a panel over the page.

  1. 1
    Drag this to your bookmarks bar
    Mirror this page
    No bookmarks bar? Copy the code and paste it as the address of a new bookmark.
  2. 2
    Open a page and click the bookmarkA toast confirms the run. Works on local builds, staging behind a VPN, and pages you are signed in to.
  3. 3
    Point, read, fixPoint at the page and the row lights up; point at a row and the element is outlined. Switch between Spoken, Preview, Nodes and JSON.
  4. 4
    Dock, minimise, closeDock to the bottom on wide pages. Minimise leaves a pill with the counts. Close removes everything it added.

Package

In your build and your tests

The same engine as a function. Give it a DOM node, get the reading order back as data: role, name, level and flags per item, in order.

  1. 1
    Install
    npm install screen-reader-mirror
    import { linearize } from "https://cdn.jsdelivr.net/npm/screen-reader-mirror@0.2/+esm"
  2. 2
    Run itThree lines in the console, a script, or a test.
  3. 3
    Fail the build on flagsAssert that nothing is flagged, or snapshot the list so a changed reading order shows up in review.
Quick start
import { linearize } from "screen-reader-mirror";
// role, name, level, flags, in reading order
const items = linearize(document.body);
console.table(items.filter(i => i.flags));
In a test
import { linearize } from "screen-reader-mirror";

test("the form reads in order with nothing unnamed", () => {
  render(<BlueBadgeForm />);
  const items = linearize(document.body);
  expect(items.filter(i => i.flags)).toEqual([]);
  expect(items.map(i => i.name)).toMatchSnapshot();
});
What comes back
[ { role: "heading", name: "Apply for a Blue Badge", level: 1 },
  { role: "textbox", name: "", flags: { unnamed: true } },
  { role: "img", name: "", flags: { missingAlt: true } },
  { role: "link", name: "Continue" } ]

Browser extension

For signed-in pages and live apps

The mirror in the browser's own side panel. Nothing is injected into the page layout, it re-runs as the page changes, and it can follow keyboard focus.

  1. 1
    Install and pin
    Chrome and EdgeFirefox
    From the stores, or install the signed build yourself if your organisation blocks store extensions. The toolbar badge shows the flagged count for the current tab.
  2. 2
    Open the popupCounts for this tab, the three switches that matter most, and one button that opens the side panel. The popup never holds the list; it is too small to read a page in.
  3. 3
    Work in the side panelSpoken, Preview, Nodes, JSON. Follow focus moves the highlighted row as you tab through the page. Alt+M opens and closes it.
  4. 4
    SettingsSpeech phrasing (generic, or closer to NVDA or VoiceOver wording), what gets said, what happens on the page, theme and text size, shortcuts. The bookmarklet has the same settings plus a dock position.

Install it yourself

Signed build, published checksum

Every release is also attached to the GitHub release as a signed package with a SHA-256 checksum, so you can install without a store, or verify what the store gave you. Same code, same version number.

  1. 1
    Download the package for your browserFirefox: a Mozilla-signed .xpi, installs directly. Chrome and Edge: a .zip of the unpacked extension, since stable builds of Chromium do not install .crx files from outside the store.
  2. 2
    Check the checksumCompare the hash with the one on the release page. If it differs, do not install it and tell us.
  3. 3
    InstallFirefox: open the .xpi and accept. Chrome and Edge: chrome://extensions, turn on Developer mode, Load unpacked, choose the unzipped folder. For a whole team, IT can allow the extension ID by policy instead.

Reading the output

Four views, one list

Every surface shows the same reading order four ways. Only the first is speech; the rest are there to help you find and fix.

  • SpokenWhat a screen reader says, in order, and nothing else. Notes in the dashed yellow box are from the mirror, not the screen reader, and say why a row is flagged.
  • PreviewThe same HTML with its CSS removed. Structure that survives without styling is structure a screen reader can use.
  • NodesPosition, role, name and flag per item. The table for people who want the data.
  • JSONThe list as text, for an issue, a snapshot or a script.
  • A flag means worth checkingToday: no accessible name, missing alt. Not a score, not a verdict. Fix it, run again, then confirm with a real screen reader and real users.

Everything beyond the first step lives in the documentation: testing beside NVDA, running it in CI, the full install guide and the API.
