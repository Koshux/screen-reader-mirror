1 · Bookmarklet

One drag, then one click on any page

A bookmarklet is a bookmark whose address is a small script. Clicking it runs the script on the page you are looking at. Ours loads the engine from a CDN, reads the page, and draws the mirror panel over it.

  1. 1

    Show your bookmarks bar

    Chrome and Edge: Ctrl + Shift + B (Cmd + Shift + B on a Mac). Firefox: right-click the toolbar, tick Bookmarks Toolbar. Safari: View › Show Favourites Bar.

    You should see a row of bookmarks under the address bar.

  2. 2

    Drag the button

    On Getting started, press and hold "Mirror this page", drag it up to the bar, let go.

    You should see a new bookmark called Mirror this page. If not: right-click the button, choose "Bookmark link" or "Add to favourites". On a phone or tablet, dragging does not work; copy the link and paste it as a bookmark's address.

  3. 3

    Click it on a page

    Open any page you want to check and click the bookmark once.

    You should see the panel on the right side of the page within a second or two, with the list already filled in. If not, see the callouts below.

When it does not run

"Refused to load the script" or nothing happens. The page has a Content Security Policy that blocks outside scripts. Banks, government sites and many internal tools do this. The bookmarklet cannot get around it, by design. Use the extension, which is allowed to run where page scripts are not.
  • Browser pages (chrome://, about:, the Web Store, PDFs): no script can run there. Nothing to mirror.
  • The panel appears but is empty: the page rendered after the click. Click the bookmark again.
  • A page with frames: same-origin frames are read; cross-origin ones show one row, "document, unreachable".

Versions

The bookmark loads the latest release each time. A small "Update available" line appears in the panel footer when the bookmark itself (the script in the address) is older than the current one; drag the button again to replace it. To freeze on a version for a long test, use the pinned button on Getting started: its address names the version, such as @0.4.1, and never changes under you.

Remove it

Right-click the bookmark, Delete. Nothing else was installed.

2 · Package

The engine, in your code

npm install screen-reader-mirror
# or
pnpm add screen-reader-mirror

Or with no build step at all, straight from a CDN as an ES module:

<script type="module">
  import { linearize } from "https://cdn.jsdelivr.net/npm/screen-reader-mirror@0.4/+esm";
  console.table(linearize(document.body));
</script>
  1. 1

    Call it on an element

    import { linearize } from "screen-reader-mirror";
const nodes = linearize(document.querySelector("main"));

    You should get an array of plain objects: role, name, sometimes level, flags, live, ref. See API.

  2. 2

    Put it somewhere useful

    Three common homes: a debug-only overlay in your app that lists the nodes beside the UI; a unit test that snapshots the list (CI › In a unit test); a Storybook addon panel.

  3. 3

    Pin and update

    Pin the minor version (^0.4.0). The changelog marks any change to the output shape as breaking, even in 0.x, so a snapshot will tell you before a user does.

  • TypeScript types are included. Tree-shakeable ESM, sideEffects: false.
  • Two runtime dependencies: dom-accessibility-api and aria-query. No others, no network calls.
  • Works in jsdom and happy-dom; pass getComputedStyle when yours differs from the browser's.

3 · Browser extension

The everyday one

Chrome and Edge at launch; Firefox when its side panel API settles. The extension runs where bookmarklets cannot, keeps settings, shows a badge count, and can read the browser's real accessibility tree.

  1. 1

    Install from the store

    Open the store page, click "Add to Chrome" (or Edge), confirm.

    You should see a puzzle-piece icon light up top right, and a one-time welcome tab: three short lines on what it does, what it never does (send data), and a button to pin the icon.

  2. 2

    Pin the icon

    Click the puzzle piece, find screen-reader-mirror, click the pin.

    You should see the sr icon in the toolbar. On pages it can read, a small number appears on it: how many rows are flagged. If the icon is grey with no number, the page cannot be read; see below.

  3. 3

    Open the side panel

    Click the icon. The popup shows the count and two buttons: "Open side panel" and "Settings".

    You should see the panel on the right of the browser, outside the page, with Spoken, Preview and Nodes tabs. The page keeps its full width; nothing is injected into its layout.

Re-run on change

On by default. When the page's DOM changes the panel re-reads it after things settle, keeps your place by matching rows to their elements, and strikes through rows that disappeared for one run so you can see what left. Turn it off for pages that update constantly (dashboards, chat) and use the Re-run button instead.

Remove it

Right-click the icon, Remove from Chrome. Settings and pairing go with it.

4 · Install it yourself

Unpacked, from a release you have checked

  1. 1

    Download the release zip

    From the GitHub releases page, extension-0.4.1.zip and SHA256SUMS.

  2. 2

    Check the sum

    sha256sum -c SHA256SUMS      # Linux
shasum -a 256 -c SHA256SUMS  # macOS
certutil -hashfile extension-0.4.1.zip SHA256   # Windows, compare by eye

    You should see "OK" beside the file name. If not, do not install it; download again from the releases page.

  3. 3

    Load it

    Unzip. Open chrome://extensions, turn on Developer mode (top right), click "Load unpacked", choose the unzipped folder.

    You should see the extension card with a version number and no errors. Chrome will remind you about developer-mode extensions on each start; that is expected.

Updates are manual: download the next zip, check it, Load unpacked again over the same folder.

5 · CLI

For CI, for many pages, and for the NVDA bridge

  1. 1

    Have Node

    Node 20 or newer. Check with node --version. If there is no Node, install the LTS from nodejs.org and open a new terminal.

  2. 2

    Run it once

    npx screen-reader-mirror https://example.com

    You should see a one-off download on first run, then the reading order as a list in the terminal. If it says a browser is missing: npx playwright install chromium, once.

  3. 3

    Choose what you are here for

    CI: Continuous integration. Testing beside NVDA: Testing with NVDA. Every flag: CLI reference.

Install globally if you prefer: npm i -g screen-reader-mirror. In Docker, use the Playwright base image so the browser is already there.
